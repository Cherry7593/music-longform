# V4.0.3 — 恢复连续编码，保留多视频并行

## 改动范围

- 删除生产静态 1 秒片段生成、指纹缓存读取/写入、`-stream_loop` 与 `-c:v copy` 视频轨循环复制路径。没有增加 10 秒、30 秒缓存替代方案。
- 静态图片通过必要的 `-loop 1` 输入持续显示，并**连续编码完整画面**。音频仍为原有完整曲目处理：不循环、不拉伸、不补静音、不裁歌凑最短时长。
- CPU、QSV、NVENC 共用的连续编码参数恢复 **`-g 300`**（30fps 下约 10 秒）。删除 x264 私有 `keyint=30:min-keyint=30`、`open-gop=0:scenecut=0`，以及片段拼接用的 `-bf 0`、`-flags +cgop`、NVENC `-forced-idr 1` 强制限制。各编码器既有预设、质量与 VBV 参数保留。
- 输出不降规格：**1920×1080、30fps、H.264/yuv420p、AAC 192kbps 目标码率、48kHz 双声道、MP4 faststart**。音频简单程度可能使 AAC 实际平均码率低于目标；前后使用同样的 192k 参数。
- 编码器能力探测仍使用短编码、逐帧探测和完整解码；它不是生产片段缓存。探测允许正常 B 帧，并拒绝非有限时长/时间戳。
- 硬件初始化失败、实际编码失败或成片校验失败，保留安全回退：最多改用一次连续 CPU 编码并完整校验。CPU 失败或取消不再次重试，不重新进入已删除的复用分支。
- 连续输出的空间预约包含完整视频、AAC、faststart 的第二份空间和余量；任务池调度算法未重写。

**保留**：跨合成项目共享资源池、并发和线程上限、CPU/内存/GPU/磁盘预算、独立进度和取消、普通失败隔离、恢复、成功任务不重复合成；有界音频处理、分组与转场、素材校验、指纹验证、安全发布及使用记录。

没有修改提示词导入、API 传输、凭据、素材管理实现或旧版冻结基线；没有恢复旧单视频工作台，没有处理其他启动问题，没有升级依赖或安装工具/驱动。

## 设置与历史数据

- 设置页删除“静态画面缓存复用”选项及相应说明，保留并行数、线程数和编码器选项。
- 设置版本仍为 V5。严格 schema 允许读取历史 `render.staticVideo: true/false`，随后剔除；保存后不再写入。其余陌生字段和无效参数仍拒绝。
- 历史执行尝试中的 `staticVideo` 诊断字段仍可读取，新执行始终记录 `false`。
- 旧 `.render-cache/music-static-v4` 不再使用，但不自动删除。素材库、原文件和历史成片均不清理、不重新处理。

## 实际定向对照（2026-10-06）

### 条件与计时边界

- 改动前先运行并保留 V4.0.2 结果，再用相同 SHA-256 的原素材运行修改后版本。
- 两张 1920×1080 的人工细节风景图：建筑窗格、草地细线、山体轮廓、16px 小字和轻微表面纹理；**不是纯色图，也不冒充真实照片**。
- 每条使用两首各 91.5 秒的固定 48kHz 双声道 FLAC，3 秒交叉淡化，输出精确 180 秒；不把音频循环到目标时长。
- 两个独立合成项目同时提交，每个一条输出；固定 **QSV、每任务 2 线程、并发 2**，前后均未发生 CPU 回退。1080p30 与音乐参数一致。
- “整批完整耗时”从两项目规划开始，到全部安全发布、视频资产登记/完整解码及使用记账完成。素材创建/导入、额外包分析、抽帧、音频比对及播放器检查不计入该时间。
- 两次均从隔离的新数据目录开始；不清理 OS/驱动缓存。没有运行之前的小时级性能矩阵。

### 数值

体积使用十进制 MB（1 MB = 1,000,000 bytes）；视频码率按实际视频包总字节数 / 180 秒计算，不把音频和容器算进去。

| 成片 B 文件大小 | 93,506,190 bytes（93.51 MB） | 12,399,459 bytes（12.40 MB） |
| A 视频轨平均码率 | 4,168,880 bit/s | 433,459 bit/s |

| B 单任务运行→发布/入库耗时 | 47.172 秒 | 75.414 秒 |

| 实际输出进程并行峰值 | 2 | 2 |

管线自身（素材探测→混音→编码→完整解码，尚未完成队列发布入库）A/B 耗时：修改前 27.757/28.404 秒，修改后 64.044/63.931 秒。它与上表整批完整耗时不是同一个指标。

**结论仅适用于这组 3 分钟样本**：体积明显改善，整批耗时增加，真实跨项目并行仍成立。这是取消片段复用并恢复连续编码参数后的组合效果，不是单独测量某一个参数的收益。不能据此外推一小时视频或承诺其他素材/硬件的固定比例；历史约 40 秒的单条差异也不是复用的独立收益，不能声称取消后“一小时只慢 40 秒”。

### 画面、音频和播放

- 两条成片前后均为 5400 帧，视频与音频流均为 180.000 秒；完整解码通过。
- 在开头、中间 90.4 秒、结尾 179.9 秒进行全分辨率 YUV 抽帧及准确跳转解码，规格保持不变。相对相同图片转换基准，A 最低 PSNR 前后均约 43.275 dB，B 均约 43.319 dB。未通过降低画质/分辨率/帧率换取体积。
- 使用本机 Edge + Python Playwright 实际播放四个前后成片，共 16 次鼠标拖动进度条、继续播放及播放到结尾，均通过；无页面错误或外部请求。此处是实际解码播放，不是只检查文件头。
- 三种转场的中间无损 PCM 与冻结 V3.1 基线逐样本对照，最大差值为 0。
- 两组 3 分钟成片的解码音频均为每声道 8,640,000 个样本。最初要求整个 AAC 解码字节哈希相同的断言未通过，因此保留原始失败报告并追加包/逐样本诊断：各 8439 个 AAC 包仅首个延迟包不同，其余 8438 包的负载、时间戳与长度完全一致；差异仅限最初 1024 个解码采样（约 21.33ms），之后逐样本完全一致。A/B 最大误差 0.0000095341 / 0.0000174476，均小于 1/32768；全曲 RMS 误差约 4.27e-8 / 7.67e-8。没有虚构“整个有损编码字节一致”。音频处理与 192k 参数未改动。
- 画质检查以抽帧、全分辨率数值和实际播放为依据，不声称完成了人工主观画质评审。内置工作面板浏览器不可用；独立 Edge 检查成功，截图留在隔离证据目录，没有采集全量应用截图。
