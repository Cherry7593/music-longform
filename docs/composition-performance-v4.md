## 对照内容

- 同一台 i5-12500H、16逻辑线程、约16GB内存机器，同一 FFmpeg/FFprobe、本轮同一组来源哈希、顺序、转场、画面和编码规格。保留源文件、生产/基线代码与基准脚本指纹。
- 六首不同频率的人工 **1805秒、48kHz双声道FLAC**及三张PNG。每输出使用完整两首和一张图，3秒交叉淡化，首尾各2秒淡化，关闭响度均衡，contain，最短3600秒；实际 **3607秒（60分07秒）**。
- 单条基线/优化串行各冷、热一次；三条批次基线/优化串行/受控并行2各冷、热一次，共 **10个实验、22个输出**。单条不重复做无法体现并发的并行实验。
- 基线明确注入冻结 `tests/fixtures/video-pipeline-v31.ts`，使用冻结 V3.1 BatchJobManager、库、回执与串行调度；不是把 V4 管线冒充旧基线。
- V4 使用真实 WorkbenchDB、AssetStore、CompositionProjects、CompositionQueue、ResourcePool、PublicationStore、DiagnosticStore；没有渲染替身，也没有借助 validated 标志绕开完整验证。
- 旧基线固定 **libx264 / ultrafast / stillimage / 4编码线程**。V4 本轮显式 **auto编码器、静图片段路径、每任务线程上限2**，串行和并行只改变池上限1/2。这是“旧执行方式对照新配置/管线”的整体效果，不是同编码器同线程的单因素算法实验，也不是以已有4线程/ultrafast作为新优化。
- 输出规格保持1920×1080、30fps、H.264/yuv420p、AAC192kbps/48kHz双声道、MP4 faststart。音频不循环、裁切、拉伸或补静音；静图片段复用仅作用于画面轨道。

## 计时边界

主 `endToEndMs` 从**开始规划**计到全部任务完成安全发布和使用记录核对；包含提交、排队、来源验证、管线、完整输出解码、发布、V4视频入库及独立使用记账，不包含 GUI 绘制延迟。

- `planMs`：规划及固定分组检查；基线使用其原有 revise，V4读取持久化的明确分组。
- `confirmationMs`：start调用耗时。它与后续确认起点计时有包含关系，不能简单再相加。
- `queueMs`：确认调用开始至任务真实 analyzing 状态，**包括提交过程**，不是只测资源池睡眠。
- `runningMs`：analyzing 至 succeeded，包含发布/入库等任务尾部工作。
- `latencyFromConfirmationMs`：确认起点至该条成功；串行后面的条目包含前序等待。
- `pipelineMs`：renderMedia实际调用区间；只覆盖管线，不含全部发布和入库成本。
- `stages`：tools/probe/audio/mix/encode/validate/publish；重入阶段聚合。直接音频图将解码与混音合并在mix，audio只记录准备时间。发布阶段可能包含资产登记的完整视频解码，不称作只有rename的开销。

**额外工作必须披露：**旧V3.1没有视频资产库；V4在管线完整解码后，视频登记还做一次实际完整验证，该成本包含在主计时。最终结果不是仅“编码完成”的秒数。

`setupMs` 单列，包含各模式首次建立元数据及导入人工素材，未纳入主计时。cold/warm共享同一context，因此同一个setup值会在两行出现，不能重复计入整轮总成本。独立的成片规格、每首频率顺序、首/中/末帧一致性和输出SHA检查在主计时后执行，`externalVerificationMs`单列；生产完整解码从未移出主计时。

## 应用缓存与资源测量

- cold仅清除这个新夹具自己的持久验证证据、重新打开存储，并清空编码器证据缓存；静图片段缓存起始为空。保留资产ID和来源hash，不改真实数据。
- warm紧接同一context的cold完成后执行，复用验证证据/静图片段。**没有清空OS、磁盘控制器或显卡驱动缓存**，不能称作系统级冷启动；编码器短测证据仍受TTL及实时设备/驱动指纹限制。
- ResourcePool在实际机器资源上决定启动，不替换资源采样、不绕开磁盘预检。报告真实任务区间和引擎FFmpeg/FFprobe区间重叠，不以启动Promise的时间代替真实工具并行。
- 约750ms加查询开销的采样：只计持有的Node/FFmpeg/FFprobe PID工作集，另采本次`.work-*`/`.render-cache`大小和系统剩余内存。成功需`errors=[]`且实际捕获媒体PID。
- 内存/临时盘峰值和CPU累积均为**采样下界**；短命子进程可能漏采、共享工作集可能重复计数。不测GPU利用率，不据此宣称整机峰值或CPU节省百分比。磁盘预约值不是测量峰值。
