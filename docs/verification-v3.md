## 实现与边界

1. **全局素材库**：音乐/图片分开，原生多选本地导入、精确 SHA-256 去重、搜索、状态筛选、30项分页及跨页全选、试听/图片预览/另存为/定位。
2. **自动汇总**：旧项目原路径引用，不搬移媒体；生成会话自动创建，新生成且已落盘的音乐/图片幂等入库。本地登记失败不再次调用生成接口。
3. **真实使用关系**：成功成片回执决定使用次数；排队、试听、失败、取消不算。部分成功分别记账，重启与另存为不重复计数。历史精确时长无法可靠判定的曲目显示待核对。
4. **批量规划**：一图一视频、整首分配、同批不重复、全部所选音乐使用一次。最短时长1–360分钟，默认60；实际扣除交叉淡化重叠，不为凑整裁歌，不循环或补静音。
5. **预览与队列**：曲目移组/排序后重新校验；提交不可变快照、全局串行调度、完成当前后暂停、取消、仅继续未成功项及重启恢复。
6. **安全发布**：素材前后指纹核对、真实解码时长复核、完整输出解码、同卷不覆盖发布、预持久化发布意图及成功回执。已发布而状态保存中断可以对账，不重渲染成功项。
7. 保留 Mureka、硅基流动 Qwen-Image、费用确认、原项目自动保存和单视频流程。未接入本地AI模型或其他服务。

导入支持 MP3/WAV/FLAC/AAC编码M4A、单帧PNG/JPEG/WebP；音频1GiB/6小时、图片40MiB/16,777,216像素/8192px每边，每次最多500个文件。库记录最多50,000，单条元数据2MiB、总元数据128MiB、每素材最多500个来源。所有上限有结构和内容校验。

### 三个一小时视频的实测

测试音频是60种不同频率的人工合成FLAC，不代表AI音乐质量。三张图片分别使用PNG/JPEG/WebP。每组20首，3秒交叉淡化：`20×185−19×3=3643`秒。

| 成片 | 实际时长 | 文件大小 |
|---|---|---|
| 视频1 | 3643秒（60分43秒） | 100,798,019字节 |
| 视频2 | 3643秒（60分43秒） | 104,176,575字节 |
| 视频3 | 3643秒（60分43秒） | 100,222,697字节 |

- 全流程用时 **1210.179秒**，含夹具生成、导入、规划、串行渲染与检查；并非对其他硬件的速度承诺。
- 三条均为1920×1080、H.264/yuv420p、30fps、AAC48kHz双声道；音视频时长一致。
- 逐曲中点频率抽样确认实际顺序与分组；60首均分配一次、跨视频无交集；没有音乐循环或静音填补。
- 每条视频首/中/尾静态画面抽样通过，并对比对应源图片；引擎完整解码验证通过。
- 63个素材使用次数均为1；重新加载库与回执后不增计数。
- 完整机器报告：`docs/batch-video-verification.json`。
- 原始输出位于会话临时目录 `yt-v3-batch 4oyXto/总素材库/批量视频/三个一小时批量验收-9c3d38aa-1077-4ff9-8d63-8abfcdc0eff8/videos/`。临时文件随会话清理，报告已复制至项目文档。

### 实测中修复并回归的问题

- 重启进入历史项目时改为优先恢复上次打开项目，而非误选最近更新项目。
- 原生选择器关闭后仍保持导入锁，直到本地文件处理结束。
- 最后一条成片成功时，以整批完成为准，即使此时请求暂停；恢复/继续也修正已全部成功但暂停的状态。
- 继续过程中等待工具检查时发生取消，取消优先，不能把任务改回待运行。
- 库素材和批次视频“另存为”纳入本地任务追踪，正常关闭等待复制结束。

上述修改后已通过427项单元测试、7条桌面流程及短批量重测；没有因这些队列/界面修正更改长视频的音频或编码算法。
