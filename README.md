# 油管视频生成 V3.0

Windows 本地工作台：总素材库、AI 音乐/图片生成、完整曲目自动分组、批量长视频合成。音乐仍使用 Mureka，图片仍使用硅基流动中国站 Qwen-Image。

## 打开与使用

源码仓库不包含已打包的 EXE；首次使用请按下方“从源码运行与打包”构建。打包后运行 `dist/油管视频生成-3.0.0-Windows-x64.exe`。这是未签名个人便携版，运行成品无需 Node.js；音乐校验和视频合成需要本地 FFmpeg / FFprobe。

1. **素材库**：音乐、图片分开管理。点击“导入音乐/图片”，可多选本地文件；只复制到本地，不上传网络。旧项目素材也会汇总到这里。
2. **素材生成**：直接填写音乐/画面描述，无需先建项目。在“设置 → API 配置”填写自己的 Mureka、硅基流动 Key；生成前仍需费用确认。成功保存的素材自动入库。
3. 在库中勾选音乐和图片。支持名称搜索、已用/未用筛选、跨页全选、试听、图片放大、另存为和定位文件。
4. **批量合成**：设置最短时长（默认 60 分钟），点击“规划分组”。每张图片生成一条视频，所选音乐全部且仅分配一次。可在预览中移组、上下排序，再一键提交。
5. **队列与历史**：逐个合成，显示实际进度。可完成当前后暂停、继续、取消整批、只重试未成功项；已成功项不会重新渲染。
6. **历史项目**：保留旧项目及原单视频编排流程，不再是新流程的必经入口。

### 举例：60 首音乐 + 3 张图片

三张图片对应三个视频，音乐按真实时长分成三组，不机械分成每组20首。每首整曲只出现在一个视频中，不截断歌曲凑整。

若每首恰为185秒，默认3秒交叉淡化，则每组20首的实际时长为：

```text
20 × 185 − 19 × 3 = 3643 秒 = 60 分 43 秒
```

这满足60分钟下限。如果每首仅180秒，则各组只有59分03秒，不能按60分钟下限提交。软件会提示补充音乐、减少图片或降低下限，**不循环、不补静音、不自动付费补歌**。

## 素材格式与保存

- 音乐：MP3、WAV、FLAC、AAC 编码 M4A。单文件最多1GiB、6小时；实际探测并完整解码校验，不只信扩展名。
- 图片：单帧 PNG、JPEG、WebP。最多40MiB、16,777,216像素、8192px/边；保留原始字节、元数据、水印和实际格式，不接受动画。
- 每次最多选择500个文件，可继续分批导入。部分失败逐项说明，成功项保留。
- 完全相同字节按 SHA-256 去重；同名不同内容可以并存。重复导入不重置使用记录。不做听感相似检测。
- 新导入文件保存在库内，之后移动被导入的原文件不影响副本。旧项目素材仍引用原路径，不搬移或重写。
- 缺失、损坏或指纹变化的素材会显示不可用；恢复原文件后刷新，或者作为新素材导入。
- 生成成功但登记失败时，只重试本地入库，绝不因此再请求付费生成。
- 首次导入前可以选择素材库位置。已有托管素材或批次输出后不能直接换根目录，避免造成失联；本版不做自动目录迁移。

## “已使用”的含义

- 只有成功校验并发布的成片才记为“已使用 N 次”，可展开查看成片名称与完成时间。
- 勾选、规划、试听、排队、失败、取消均不计使用；排队状态单独显示。
- 一批部分成功，只标记成功视频使用的音乐和图片；重启恢复不重复计数。
- 另存为已完成视频不增加次数。成片被用户移走后，其历史使用记录仍保留。
- 已用素材可以主动再次选择；跨批允许复用，同批音乐不重复。
- 历史“完整播放”成片可确定所有选曲关系；旧精确时长导出没有保存真实解码时间线，对无法可靠还原的尾部曲目显示“历史用量待核对”，不误计为已用或未用。

## 时长、转场与输出

| 选项 | 行为 |
|---|---|
| 批量最短时长 | 1–360分钟；整首播放，允许超出，不为了凑整裁歌 |
| 旧项目“全部播放一次” | 每首一次，交叉淡化扣除重叠 |
| 旧项目“目标时长” | 保留原有精确时长裁切模式，仅在历史单视频工作区使用 |
| 直接拼接 | 顺序连接，不插入人为间隔 |
| 淡出后淡入 | 前曲淡出再播放后曲淡入，无重叠、不缩短总长 |
| 平滑交叉淡化 | 默认3秒，0.5–10秒；相邻曲目重叠部分计入时长扣除 |

- 首尾默认各淡化2秒，可设0关闭。响度均衡默认关闭；开启后对完整曲目做两遍分析。防削波不开自动增益补偿。
- 不自动删去原曲里的静音，不做节拍/调性匹配，不修改源文件。
- 每条视频最多100首、最长6小时；每批最多100条。所选音乐全部使用，过量选择会使视频明显变长，预览如实显示。
- 规划器是确定性的有限搜索，不承诺对任意整首组合求出数学最优解。未找到可行分组时可手动调整，不会把“搜索未找到”一律说成总时长不足。
- 一张图片贯穿一条视频，完整显示留边或居中裁切铺满；保持比例、不拉伸。
- 输出 **MP4、1920×1080、30fps、H.264/yuv420p、AAC 192kbps、48kHz双声道、faststart**。
- 批量与旧单视频/转场试听共用合成锁。修改界面选择不会改变已提交快照。

进入 **设置 → 视频工具** 检查环境。先查 PATH，也可选择 `ffmpeg.exe`，同目录须有 `ffprobe.exe`。本次在 FFmpeg 9.0 Windows x64 验证；程序不捆绑、下载或安装工具。

中间音轨需要额外空间，预检估算通常明显大于最终 MP4。建议使用空间充足的本地 NTFS：安全发布依赖同卷硬链接，不支持的文件系统会报错；不使用网络共享路径。校验完成后清理本任务临时文件，不清理其他进程或原素材。

## 队列、恢复与数据兼容

- 单条失败暂停该批次。继续只处理未成功项，已发布输出有指纹回执，发布与状态保存之间中断也可对账。
- “完成当前后暂停”不打断当前视频；“取消整批”停止当前及余下任务，保留成功成片。
- 关闭软件会保存队列、停止软件自己的本地进程；下次需手动继续。中断视频重新渲染，不承诺断点续编，不自动运行长任务。
- 不覆盖已完成文件。晚到的取消若发生在最终发布之后，以完成结果为准。
- 应用版本3.0.0；旧项目/设置仍为数据V3、密钥V2。新增独立V1素材库、批次及回执，不强制重写旧项目结构。

应用数据目录新增：

```text
library/config.json       固定库根目录、自动生成会话
library/index.json        全局素材索引
library/items/<ID>.json   素材详情、指纹与原始来源
video-batches/            轻量索引及批次详情
export-receipts/          准备发布/成功发布的使用回执
```

手动导入媒体在固定库根目录的 `audio/`、`images/`；批量视频在 `批量视频/<批次名-ID>/videos/`。原项目的 `project.json`、`audio/`、`images/`、`videos/`、`previews/` 保持原位。

启动继续识别 `音乐画布`、`music-canvas` 和新品牌数据目录；多份历史需选择，`--user-data-dir` 优先。V1/V2升级仍先校验、独占备份再原子保存，保留历史模型来源与Mureka密文。旧OpenAI密文只在加密迁移备份中，图片需新硅基流动Key。

备份时同时保留应用数据目录、素材库根目录和所有旧项目目录。索引损坏不以空库覆盖。已升级项目不要再交给V1/V2.0编辑；旧版程序也不会维护V3新增的全局使用记录。V1/V2/V2.1成品和历史验收记录均保留。

## API 与费用边界

- Mureka音乐业务不变；硅基流动固定 `Qwen/Qwen-Image`，每次一张，50步/CFG4，横1664×928、方1328×1328、竖928×1664，不关闭默认水印。
- Key只在软件设置中填写，通过Windows safeStorage加密；不要发送到聊天或写进源码、截图。跨电脑通常需重新配置。
- 生图连接检查只读模型列表，不代表有额度或实际生图成功。生成POST不自动重发，未知状态先核对服务商后台。
- 音乐有已保存任务ID时可恢复查询；图片同步请求中断不保证可恢复。“停止后续音乐”不撤回远端已受理任务。
- 本地导入、规划和视频合成不需要API Key，也不消耗生成额度。
- 本次开发没有调用真实密钥或付费生成；真实账号权限、余额和生成效果未验证。

本版不包含本地AI模型部署、云同步、素材删除/清库、视频素材导入、图片编辑、字幕、动态画面、多图轮播、4K或YouTube自动上传。

## 从源码运行与打包

开发验证环境：**Windows x64、Node.js 24.14.1、npm 11.19.0**。先安装 Git、Node.js，以及用于音频校验和视频合成的 FFmpeg / FFprobe。

在 PowerShell 中执行（私有仓库需要具有读取权限的 GitHub 账号）：

```powershell
git clone https://github.com/Cherry7593/music-longform.git
cd music-longform
npm.cmd ci
npm.cmd run dev
```

打包 Windows 便携版：

```powershell
npm.cmd run dist:win
Get-FileHash -Algorithm SHA256 '.\dist\油管视频生成-3.0.0-Windows-x64.exe'
```

输出位于 `dist/`，未签名；FFmpeg / FFprobe 不包含在安装包内。`node_modules/`、`out/`、`dist/`、本地配置和密钥不会上传到源码仓库。API Key 只在应用的设置页填写，不要写入源码或提交到 Git。
