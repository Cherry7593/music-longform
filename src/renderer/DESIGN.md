# 油管视频生成 · Renderer V3 design contract

- Mission: a local library desk → ordered selection → whole-song grouping → batch queue. The library opens without a project; generation opens a backend-managed session. History retains the existing project generation/video workspaces, paid confirmations, autosave and recovery. No provider, storage or rendering business rules move into the UI.
- Color tokens (existing V2.1): surface `#ffffff`, sidebar `#f5f6f8`, inset `#fafbfc`, ink `#20242b`, muted `#69717d`, border `#e5e8ed`; action `#426b9e`, hover `#345b89`, selected `#edf3fa`; error `#a83838`, warning `#8a601f`, success `#397054`. Always accompany status color with text.
- Type: Segoe UI / Microsoft YaHei UI / Microsoft YaHei / system-ui; body, inputs and buttons 16px; metadata at least 14px; section headings 20px; page titles 24px. Left-align names, forms, counts and queue information. No external fonts, scaling or tiny breakpoint overrides.
- Geometry: existing 240px light-gray desktop sidebar; 4px/8px rhythm, 8/12/16/24/32px spacing; controls 44px (compact 42px); radii 6px control / 8px surface / 12px dialog. Use stable `minmax(0, 1fr)` tracks, wrapping long Chinese names, paged music tables and image contact sheets. Long plans/results scroll vertically, never conceal broken layout with horizontal clipping.
- Do: make the four main destinations explicit; keep music rows information-dense and image contact sheets useful; show native import results per file; retain selections across categories/pages/navigation; distinguish successful usages, queued uses, uncertain history and unavailable media. Use the existing Dialog focus trap, Escape and return-focus behavior; every action has real IPC and a busy guard.
- Do: invalidate plans after any selected ID/order or option change, submit only an authoritative issue-free plan, move rather than copy songs between groups, keep submitted snapshots immutable, show only real active-job progress and completed counts. Keep names and durations from the main-process snapshots.
- Don't: decorative statistics cards, gradients, slogans, cloud/deletion/drag-drop controls, arbitrary path submission, fabricated ETA/progress, automatic paid regeneration, or claiming uncertain history means unused. No repeated generation consent bypass.
- Motion: immediate press/hover feedback, 120ms color/border transitions; existing 180ms spring-like one-shot entrance with a bounded stagger only for newly displayed items/dialogs. Respect reduced motion; no `transition: all`, generic 0.3s easing or dependencies.
- Assumptions: `src/shared/library-types.ts` and `batch-schemas.ts` are authoritative; the parent supplies native selectors, persistence, validation, migrations, media protocol, generation session and queue scheduler. The root chooser is offered only while the library has no assets. Selections and unsent batch drafts are session-local; saved batches and generation drafts are backend-persisted. Original legacy project controls/data-testids remain in History.
- Scope / verification: renderer files only, including `useWorkspace.ts` to install the managed generation project. Use isolated scratch browser fixtures explicitly labeled demo data, never real user profiles or paid APIs. Report browser, focus, responsive and reduced-motion checks separately from the parent-owned full Electron/backend acceptance.
